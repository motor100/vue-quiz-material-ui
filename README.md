# VueJS Quiz Bach Flower
#### КВИЗ анкета подбор БАДов Цветы Баха для https://naturapharma.ru

Интерактивная экспертная система для автоматизированного подбора Солей Шюсслера на основе анализа симптомов, морфотипов лица и астрологических сигнатур. Проект реализован как полноценное Full-Stack приложение с легким SPA-клиентом на **Vue 3** и изолированным RESTful-сервисом на базе **WordPress (WooCommerce)**.

## 🚀 История создания и Production-статус проекта

Это реальное коммерческое решение, разработанное для оптимизации существующего бизнес-процесса интернет-аптеки. 

**Причина разработки и рефакторинга:**
Изначально квиз был реализован сторонними разработчиками на стеке React + TypeScript. Однако решение обладало рядом критических недостатков:
1. **Отсутствие мобильной адаптации (UX):** В оригинальной версии отсутствовала навигация для смартфонов, что делало прохождение длинной анкеты (более 20 шагов) на мобильных устройствах крайне неудобным и приводило к потере конверсии.
2. **Сложность поддержки:** Архитектура React-компонента была переусложнена, что затрудняло оперативное внесение изменений в логику подбора и интеграцию с кастомным WordPress API.
3. Оригинальное приложение на React имело критическую архитектурную ошибку: парсер Excel-файлов (`xlsx`) был вшит прямо в клиентский код. Из-за этого приложение каждый раз на клиенте весило **1.1 МБ** и заставляло браузер пользователя парсить бинарный `.xlsx` файл «на лету» при каждой загрузке страницы. Поскольку данные солей и симптомов меняются заказчиком крайне редко, я принял решение изолировать парсер. В связке с ленивой загрузкой чанка это позволило сократить размер базовой сборки до **11 КБ**, убрав весь лишний оверхед по памяти и сети на стороне пользователя.

**Что было сделано:**
* Проект был полностью переписан на **Vue 3 (Composition API)** с нуля.
* Спроектирована и внедрена **удобная мобильная навигация (горизонтальный скролл-банд вкладок)**, адаптированная под экраны смартфонов, что значительно повысило глубину прохождения квиза.
* Проведен аудит производительности: внедрен динамический фоновый импорт данных Excel-дампа (Code Splitting), снизивший стартовый вес приложения до **11 КБ**.
* Полностью переработана серверная часть на PHP (кастомные REST API эндпоинты в WordPress с интеграцией под WooCommerce в папке backend-examples).


## 🏗 Архитектура системы и поток данных (Data Flow)

Приложение спроектировано по принципу разделения обязанностей (Separation of Concerns) и состоит из трех логических слоев:

1. **Компиляция данных (XLSX to JSON Parser):** Исходная матрица симптомов, весов и индивидуальных дозировок поддерживается экспертами в Excel-таблицах. На этапе сборки дамп компилируется в оптимизированный JSON-файл структуры вопросов и продуктов.
2. **Клиентская часть (Vue 3 SPA):** Нативный интерфейс без тяжелых UI-фреймворков. Выполняет пошаговый опрос, фоновые вычисления и фиксацию состояния перед отправкой.
3. **Бэкенд-сервис (WordPress / WooCommerce REST API):** Кастомные эндпоинты, реализующие двухэтапную валидацию коммерческих прав, контроль одноразовых сессий и транзакционную пост-обработку (генерация купонов, email-нотификации).

## ⚡️ Ключевые особенности и оптимизация (Фронтенд)

* **Code Splitting & Lazy Loading (Оптимизация бандла):** Тяжелый дамп вопросов (`xlsParsedDump.json` ~255 КБ) полностью исключен из базового чанка приложения. Это снизило вес стартовой сборки до **11 КБ** и обеспечило моментальный *First Contentful Paint (FCP)*. Загрузка данных анкеты происходит асинхронно через динамический импорт (`await import()`) в неблокирующем потоке (`onMounted`), пока пользователь заполняет форму личных данных.
* **Декларативный расчет (Computed Векторы):** Алгоритм накопления баллов изолирован в чистую JS-функцию. Вычисляемое свойство `calculatedResultsList` реактивно отслеживает изменения в объекте выбранных симптомов, кэшируя результаты весов для оптимизации производительности UI.
* **Паттерн "State Snapshot":** В момент завершения квиза приложение делает иммутабельный слепок результатов, выполняет POST-запрос к API, после чего полностью очищает `localStorage` и реактивное состояние формы. Это гарантирует безопасность персональных данных (GDPR/ФЗ-152) и готовит квиз к новому чистому прохождению.
* **Динамические ключи объектов:** Индивидуальные дозировки подбираются динамически прямо в шаблоне на основе вычисленной возрастной категории (`salt[currentPrescriptionKey]`), исключая громоздкие конструкции `if/else` или `v-html`.

---

## 🔒 Безопасность и бизнес-логика (Бэкенд)

* **Двухэтапная валидация доступа (WC Integration):** 
  * На первом этапе (`GET /posts/id`) бэкенд проверяет валидность транзакции через ядро WooCommerce (`WC_Customer_Download_Data_Store`), контролируя лимиты оставшихся генераций (`downloads_remaining`) и срок действия ссылки (`access_expires`). Это защищает систему от несанкционированного использования и парсинга базы данных.
  * При успешной валидации генерируется криптографически стойкий одноразовый токен сессии, который записывается в кастомную таблицу `custom_api_tokens`.
* **Принцип Idempotency (Защита от Replay-атак):** Прием результатов (`POST /authors-fbq/id`) проверяет токен и **незамедлительно удаляет его из БД** (`$wpdb->delete`) до выполнения транзакционных операций. Это гарантирует, что один токен может быть использован строго один раз.
* **Санитизация и Безопасность:** Все входящие данные от пользователя (`$request->get_json_params()`) проходят глубокую очистку нативными средствами WordPress (`sanitize_text_field`, `sanitize_email`) перед сохранением в базу данных.
* **Автоматизация маркетинга:** После успешного сохранения результатов в таблицу `fbq_results` система через REST API генерирует уникальный персональный купон на скидку в WooCommerce и осуществляет транзакционную отправку HTML-писем пользователю и администратору аптеки.

## 🛠 Технологический стек

* **Frontend:** Vue 3 (Composition API, `<script setup>`), JavaScript (ES6+), LocalStorage API, HTML5/CSS3 (BEM, Native Accordions).
* **Backend:** PHP 7.4+, WordPress Core, WooCommerce API, WP_REST_Controller, WPDB (Prepared Statements).
* **Сборка и парсинг:** Vite, Node.js (XLSX Parser).

## 🚀 Как запустить локально (Фронтенд)

1. Клонировать репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Установить зависимости:
   ```bash
   npm install
   ```
3. Запустить сервер для разработки:
   ```bash
   npm run dev
   ```
4. Собрать Production-версию:
   ```bash
   npm run build
   ```
